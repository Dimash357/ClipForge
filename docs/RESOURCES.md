# Планировщик ресурсов (1D)

Код: `studio/resources.py`. Один на процесс ClipForge; лимит тяжёлых задач между процессами остаётся в атомарном
захвате задачи очереди (`jobs._claim`).

## Что управляется
| Ресурс | Ёмкость |
|---|---|
| CPU | слоты = ядра × доля режима |
| RAM | вся память − запас режима; выдача ещё и по реально свободной памяти |
| VRAM | память карты − запас режима − чужие программы (`nvidia-smi`) − наши аренды и загруженные модели |
| NVENC / NVDEC | сессии по режиму (только при наличии GPU NVIDIA) |

## Аренда
```python
from studio import resources
with resources.manager().acquire(label='Генерация', vram_mb=3500, cpu=2, timeout=600) as lease: ...
lease, use_nvenc, use_nvdec = resources.gpu_media_lease('Рендер', nvenc=True, nvdec=True)   # иначе CPU
```
* Всё-или-ничего: запрос получает всё сразу или ждёт, ничего не удерживая. Поток, уже держащий аренду, никогда
  не ждёт вторую (сразу `Unavailable` → CPU) — взаимная блокировка невозможна.
* Очередь ожидания: приоритет задачи, затем время прихода; запрос, ждущий дольше 20 с, не обгоняется (без голодания).
* Запрос больше машины (например, VRAM без GPU) — `Unavailable` сразу, без ожидания. Ожидание отменяется вместе с задачей.
* Аренды привязаны к задаче очереди (приоритет, отмена); забытые аренды освобождаются по окончании задачи.

## Модели
`manager().model(key, loader, device=, vram_mb=, ram_mb=, group=, group_max=)` — ленивая загрузка (один раз, даже
из многих потоков), общий экземпляр, закрепление на время использования. Простаивающие модели выгружаются
(LRU): при нехватке памяти, после CUDA out-of-memory, по таймеру режима, сразу после использования в «Экономном»
режиме, кнопкой на странице «Очередь задач». Сейчас через реестр идут Whisper (одна модель за раз) и YAMNet.

Whisper: нехватка видеопамяти → выгрузка простаивающих моделей и одна повторная попытка с вдвое меньшим пакетом,
затем CPU. В отличие от отсутствия библиотек CUDA, нехватка памяти не отключает GPU до перезапуска.

## Режимы
| | Сбалансированный | Максимальная производительность | Экономный |
|---|---|---|---|
| Тяжёлых задач одновременно | 1 | 2 | 1 |
| CPU | все ядра | все ядра | половина |
| Запас VRAM / RAM | 1 ГБ / 3 ГБ | 0,5 ГБ / 2 ГБ | 2 ГБ / 4 ГБ |
| NVENC / NVDEC сессий | 2 / 2 | 3 / 3 | 1 / 1 |
| Модели держатся | 15 мин | 1 ч | выгружаются сразу |

Переключение — на странице «Очередь задач» (сохраняется в `clipforge_settings.json`) или `CLIPFORGE_RESOURCE_MODE`.
`CLIPFORGE_MAX_JOBS`, если задан, по-прежнему фиксирует число тяжёлых задач. `CLIPFORGE_GPU_WAIT` (900 с) — сколько
ждать занятый GPU, прежде чем перейти на CPU.

## Будущие модели (генерация изображений/видео, LLM, TTS)
```python
with mgr.acquire(label='SDXL', vram_mb=1500, timeout=900):          # рабочая память шага
    with mgr.model(('sdxl', 'base'), load_pipe, device='cuda', vram_mb=6500, group='image', group_max=1,
                   unload=lambda p: p.to('cpu')) as pipe:
        ...
```
Если модель не помещается в карту — `Unavailable`, вызывающий код выбирает CPU-вариант или меньшую модель.
